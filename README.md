# YOLO Labeler

学習画像を10枚ずつ選別し、YOLOの枠を修正して、M5Stack V-Training **Detection用ZIP**を書き出すWindows向けGUIです。Python 3.11以上とTkinter、Pillow、NumPy、OpenCVを使用します。外部API・モデルのダウンロードは不要です。

## 起動

作業フォルダー外の書き込み制限で指定先への配置が完了していない場合は、現在のフォルダーで `.\install-to-requested-folder.ps1` を手動実行すると、コミット済みのコードとGit履歴を `C:\Users\lator\Documents\GitHub\yolo-labeler` へ複製します。既存のファイルは上書きせず、元のリポジトリも保持します。

`launch.bat` をダブルクリックします。既存のPythonに必要なライブラリがあればそのまま起動し、不足していればこのフォルダーの `.venv` にインストールします。初回の依存ライブラリ取得にはインターネット接続が必要です。

PowerShellから起動する場合:

```powershell
cd C:\Users\lator\Documents\GitHub\yolo-labeler
.\launch.bat
```

自分で仮想環境を作る場合:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m yolo_labeler
```

## 基本の流れ

1. **新規データセット**で画像フォルダーを選びます。`classes.txt` があれば読み込みます。なければクラス名を1行ずつ入力します。先頭行がID `0`です。画像のサブフォルダーも対象です。
2. `.ylproject` の保存先を選びます。画像と同じ場所の同名TXT、または `images` と `labels` を対応させたYOLO形式を読み込みます。別のラベルフォルダーも指定できます。
3. **10枚の一覧**で捨てたい画像をクリックし、**このページを確定**を押します。選択画像は除外、残りの有効な既存ラベルは確認済みの採用になります。不足・不正なラベルや未承認候補がある画像は要修正になります。保留・要修正・既存の除外画像を自動で採用に戻すことはありません。
4. ダブルクリックまたは**枠・ラベルを編集**で、枠の追加・移動・サイズ変更・クラス変更・削除を行います。
5. **検査**で問題を確認します。一覧の画像に関するエラーをダブルクリックすると編集画面へ移動します。
6. 採用した確認済み画像が**101枚以上**になったら**V-Training ZIPを書き出す**を押します。

| 操作 | 動作 |
| --- | --- |
| 一覧でクリック、`1`〜`0` | このページの除外予定を切り替え |
| `Enter` | このページを確定 |
| 左右キー | 前・次ページ |
| `Ctrl+Z` | 直前の判断・編集を取り消し（現在の起動中、最大40操作） |
| `Ctrl+S` | プロジェクトを保存 |
| 編集画面で`W` / `V` | 枠の作成 / 選択・移動 |
| 編集画面で`Delete` | 選択中の枠を削除 |
| 編集画面でホイール / 右ドラッグ | 拡大縮小 / 表示位置の移動 |

ページ移動・絞り込みを行うと、未確定の選択は解除されます。確定操作ごとにプロジェクトを保存します。最後に見ていたページや絞り込みも、保存・正常終了時に記録されます。

## UnitV-colorの半自動ラベリング

**半自動ラベリング**は、既存の `UnitV-color/tools/yolo_labeler/label.py` を使います。元スクリプトの同梱コピーと検出結果を生成するアダプターで構成し、元プロジェクトへのインストール・変更はしません。

- 自動しきい値（Otsu）、HSV補助抽出、近接成分の結合、余白を既存処理と同じ方法で設定します。
- 固定クラス、または `start,end,class_id` のCSVで画像番号とクラスを対応させます。記号の種類は推測しません。
- 最初のプレビューは現在のページの先頭画像です。条件を調整してから一括生成します。
- 候補生成の対象は未承認画像です。採用・除外済み、または編集画面で確認済みの画像は保護します。
- 生成結果は候補として保存します。編集画面の**候補で枠を置き換える**か**候補をすべて破棄**で判断し、その後に保存します。検出なしの候補も明示的な確認が必要です。
- 基本は**1画像1対象**の黒い文字・記号向けです。複数対象の枠は編集画面で追加します。

範囲CSVの例:

```csv
start,end,class_id
1,100,0
101,200,1
201,300,2
```

番号は両端を含み、クラス順はデータセットに合わせます。クラスの並び順は自動では変えません。

**外部YOLO候補を読み込む**では、画像と対応するTXTを候補として取り込めます。選択する候補フォルダー直下に、同じ順序の `classes.txt` が必要です。既存のUnitVツールが生成した `labels` フォルダーを使う場合は、元データのクラス順が一致する `classes.txt` を追加してから選択します。

## 品質・重複の検査

ぼけ、黒つぶれ、白飛び、小さな対象は確認候補として表示します。**これらの指標だけでは自動除外しません。**

**破損・重複を自動除外**は、品質検査後、未確認の破損画像と、ラベルが同じ完全重複だけを対象にします。代表画像を1枚残します。ラベル不一致、未承認候補、確認済み画像、検査後に内容が変わった画像は自動除外しません。除外は状態変更で、元ファイルを削除しません。

近似重複の自動グループ化・学習済みモデルによる品質判定は、今回の版には含みません。

## 保存と出力

`.ylproject` には、元画像へのパス、編集済みラベル、候補、選別状態、品質指標、判断履歴を保存します。前回の保存内容は `.ylproject.bak` に残します。元の画像とTXTは書き換えません。元画像を移動した場合は、プロジェクトを開くときに移動先を指定できます。

ZIP直下は `classes.txt`、`v-training.config`、連番の `000001.jpg` と `000001.txt` …になります。親フォルダー、確認画像、履歴、レポートは含めません。画像はRGB JPEGへ変換し、EXIFによる回転を適用せず、枠と同じ元ピクセル座標を使います。表示用の枠は焼き込みません。

出力前とZIP完成後に、枚数、枠、クラス、対応ファイル、画像の読み込み、ZIP構造、CRC、200MB以下であることを検査します。元画像が読み込み後に変わっている場合は出力を中止します。同名ZIP・レポートは上書きしません。元ファイル名との対応表を `ZIP名.report.json` に保存します。

公式説明は「100枚より多い」、失敗通知の例は「100枚以上」のため、このツールでは**101枚以上**を出力条件とします。空TXTの背景画像はV-Trainingの受理条件を確認できていないため、GUIの提出ZIPではブロックします。`rename.bat` は失敗通知の例にはありますが公式手順で必須とされていないため、追加しません。サービス側での学習成功は未検証です。

6桁で保存したYOLOラベルの丸め誤差を考慮し、画像端から正規化座標で `0.000001` 以内のはみ出しだけを読み込み時に補正します。それを超えるはみ出しはエラーとして扱います。
