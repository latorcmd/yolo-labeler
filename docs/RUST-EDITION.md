# YOLO Labeler 0.3 — 使い方

Windows x64向け。GUIはAntiWebUI、画像処理はRustのimage/imageprocです。Python・OpenCV・モデルのダウンロードは不要です。

## 起動・保存

ZIPを展開して `yolo-labeler.exe` を起動します。リポジトリでは `launch.bat` または `launch-rust.bat` を使います。配色はWindowsのアプリモードへ追従します。白基調の画像・選択枠アイコンを組み込んでいます。

保存形式は `.ylp2`（内部バージョン2）。同名の `.ylp2.assets` フォルダーと一緒に保管・移動してください。バージョン1は判断を維持して読み込み、未判断の正常なラベルだけ初期採用へ移します。旧 `.ylproject` には対応しません。バージョン2を旧アプリへ戻して開くことはできません。

## 画像を追加する

1. 最初は「新規」で画像フォルダーと保存先を選びます。classes.txtがなければ保存用クラス名を1行ずつ入力します。先頭行がID 0です。
2. 「画像を追加」では複数ファイル、「フォルダー追加」では子フォルダーも取り込みます。別のラベルフォルダーも指定できます。
3. 今回追加する画像が「対象あり」か「対象なし」かを選びます。混在する場合は分けて追加してください。
4. 対象ありでは固定クラス、または `start,end,class_id` の番号範囲CSVを指定します。正常な既存枠を優先し、枠がない画像だけ標準設定で自動検出します。自動枠は採用され「自動」と表示します。H/S/Uなどの種類を画像から見分ける機能ではありません。
5. 対象なしでは背景として採用します。既存の正常な対象枠がある場合は、対象ありへ変更するか追加を中止します。

元画像・元TXTは変更せず、assets内にコピーします。同名の別画像は保持し、同じ元パスの再追加はスキップします。classes.txtは現在と同じID順・名称が必要です。中止・コピー失敗時は未公開の追加を取り消し、公開後の保存失敗は取込記録から復旧します。画像追加そのものはUndo対象外です。

## 不要な画像だけ除外する

正常な枠、または背景として明示された画像は初めから採用です。クリックか数字キー1〜0で採用／除外を即切り替えます。ページ確定操作はありません。除外しても元画像は消しません。Undoは起動中の直近40操作までです。

ラベル不正・未作成・画像破損・未承認候補は要確認となり、出力を止めます。「枠を編集」で直すか、不要なら除外します。保留画像も出力しません。初期採用や自動枠の採用は、人が確認済みという意味ではありません。

ファイル名は数字を数として並べ、1、2、3、10、100の順になります。カードにはラベル名・採用状態・背景・要確認理由を表示します。

## ラベルの表示名・枠編集

「詳細・設定」→「ラベル表示名の対応表」で、H/S/U等をギリシャ文字などへ表示だけ変更できます。異なる名前は「表示名 (H)」と併記します。空欄は元の名前を表示します。YOLOのクラスID、classes.txt、外部候補との照合名は変わりません。

「枠を編集」から追加・移動・リサイズ・クラス変更・削除ができます。「背景にする」で枠なし背景へ変更し、枠を描くと対象ありへ戻ります。背景の変更もUndo対象です。EXIF自動回転は行いません。

## 操作とショートカット

| 場面 | キー | 動作 |
|---|---|---|
| 一覧 | ← / A、→ / D / Enter | 前・次ページ |
| 一覧 | マウスホイール | 上で前、下で次ページ。連続イベントはまとめる |
| 一覧 | 1〜0 | 対応画像の採用／除外を切替 |
| 共通 | Ctrl+N / Ctrl+O / Ctrl+S | 新規・開く・保存 |
| 一覧 | Ctrl+Z | 判断・保存済み編集のUndo |
| 編集 | V / W / P | 選択・描画・パン |
| 編集 | Delete / Ctrl+Z | 選択枠の削除・編集中のUndo |
| 編集 | ホイール / 枠・四隅のドラッグ | ズーム・移動・リサイズ |
| 編集 | Ctrl+Enter / Ctrl+S | 保存して採用 |
| 編集 | Esc | 編集をキャンセル（変更があれば確認） |
| 共通 | F1 | 使い方・ショートカット |

文字入力・IME変換・メニュー操作中は一覧ショートカットを抑止します。選別とページ位置は裏で順番に保存し、連続操作の書き込みをまとめます。「未保存」が出たらCtrl+Sで再試行してください。終了・プロジェクト切替・出力前には最新保存の完了を待ちます。

## 詳細処理・出力

詳細パネルに半自動候補・品質検査・重複検査・外部YOLO候補をまとめています。追加時の自動枠とは別に、ここで生成・取り込んだ候補は承認または破棄が必要です。手動判断や確認済み画像は自動処理から保護します。外部候補は追加元を選び、その元相対パスで照合します。

暗さ・ぼけ等は参考指標で、自動除外しません。保護条件と検査指紋が一致する破損・完全重複だけを、明示した操作で除外できます。

V-Training Detection ZIPは採用101枚以上、各実クラスの枠、200,000,000bytes以下を要求します。背景も画像＋空TXTで含めます。背景を実クラスとして追加しません。**V-Trainingサービス側で背景が受理されるかは未確認です。** アップロードは行いません。

ZIP直下にclasses.txt、v-training.config、連番のRGB JPEG/TXTを置き、元画像hash・構造・ラベル・CRCを再検査します。表示名は出力クラスへ反映しません。元名対応はZIP外のreport.jsonへ保存し、既存ZIP・レポートを上書きしません。

## 開発・検証

Rust stable MSVC、Visual Studio C++ Build ToolsとWindows SDKが必要です。`./build-rust.ps1` でEXE・LICENSE・依存ライセンスを含む配布ZIPを作ります。`cargo test --workspace --locked` で検証します。

`--project PATH.ylp2` で起動時に開けます。`--qa-screen OUTPUT.png --project PATH.ylp2 --dark --scale 1.5 --edit` は画面検証用です。`--qa-small` は960×540論理ピクセルを検証します。`--qa-page-bench` と `--qa-stress` は実際のページ操作経路を通り、指定した検証用プロジェクトの画面状態を保存します。

検証済み・未確認の区別はリポジトリの `docs/RUST-VALIDATION.md` を参照してください。アイコンの再生成は `tools/create-icon.ps1` です。
